Key learnings & principles
Execution discipline (enforced strictly):

Three-step pattern: check command → stop for operator review → backup+implement → stop → verify. Never combine steps. Alejandro catches every collapse.
Read before write: always verify current file contents before proposing edits. Drafting without reading the existing file is not tolerated.
Verify before reporting: always grep/cat/query to confirm changes took effect. Agents (and Claude) report edits as done without verifying — this is a standing failure mode.
Write complete replacement files for boot file edits, not incremental sed commands.
claude.ai project knowledge at /mnt/project/ is read-only. Session logs are uploaded manually by operator.
Never propose file edits without first reading the existing file. Never author planning documents when the operator's preference is execution.

Agent behavior principles:

Principles without procedures don't change agent behavior. Forcing functions (FACT_LIST_START/END markers), decision trees with worked examples, and step-by-step protocols change behavior.
Agents write directly to wrong Qdrant collections without enforcement. Collection discipline requires IF/THEN/STOP forcing functions in boot files, not descriptive checklists.
Clarity is not permission. ASK FIRST when modifying: shared infra, boot files (AGENTS/MEMORY/SOUL/BOOTSTRAP), brain convention files, anything that feels "obvious" or "clearly right."
Sky brain (SKY-BRAIN-HANDLING-01): never modify without explicit same-turn approval — Impact3 teammates depend on it via i3drive.

Architectural principles:

Behavioral contracts only in schema/spec documents — no counts, times, token budgets, model names, or thresholds (they drift and cause confusion).
ops_intelligence is exclusively for long-term predictable protocols. Session-level forward-plan decisions belong elsewhere.
Session-level facts (FP decisions) ≠ long-term protocols. Don't store the former in ops_intelligence.
Boot files are in workspace dirs (~/.openclaw/workspace-sky/AGENTS.md), NOT agent dirs (~/.openclaw/agents/sky/agent/).
Always use named vectors ("dense": {...}), never unnamed — unnamed breaks bootstrap_context.py search.
COLLECTION_MAP in ~/bin/store_context.py is authoritative for Qdrant collection names: sky→sky_context, oss→oss_tools, research→research, setup→setup_context, operator→operator_context, ops→ops_intelligence.

Priority chain: Comms Guidelines → Strategy Blueprint → Website copy → Alejandro's direct statements → external sources. Alejandro's corrections override everything. Must be referenced in any spec touching Qdrant writes or confidence tagging.
